# Document Reviewer — ZCode 文档选区批注插件

在 ZCode 对话里**内联**打开文档（也可以固定到侧栏），直接选中文字添加批注，最后把所有待发送批注一次性交给**当前主 Agent**，由 Agent 按批注修改原始文件并逐条反馈。

支持 **Markdown（渲染 / 源码双视图）**、**TXT**、**PDF（pdf.js 文本层选中、缩放、高亮）**、**DOCX（Mammoth 转 Markdown 预览）**，中文排版与 CJK PDF 均已实测。

---

## 功能

| 能力 | 说明 |
| --- | --- |
| 打开方式 | 默认在对话中内联显示（工具结果卡片），不占插件页；顶部「展开到侧栏」可切到固定侧栏 |
| 文件浏览 | 递归扫描工作区，支持 `.md` / `.markdown` / `.txt` / `.pdf` / `.docx`，可筛选、刷新 |
| 工作区外文件 | 左侧「打开工作区外文件」可输入绝对路径，或点「浏览…」调用系统文件选择器；只读预览，批注消息指向原文件；仅用户主动打开，Agent 不能调用该入口 |
| Markdown | 渲染视图（标题、列表、表格、代码块）与源码视图切换；两种视图均可精确选区 |
| TXT | 按块渲染，长文档使用 `content-visibility` 分块优化 |
| PDF | pdf.js 渲染、自适应宽度、缩放（40%–300%）、文本层选择、跨页选区自动拆分 |
| DOCX | 原版样式（docx-preview）/ Markdown 双预览；原版预览按文档区宽度自动缩放；批注按原文文本 + 前后文 + 出现序号定位 |
| 批注 | 贴近选区的紧凑浮层（约 340px）、原文一行预览、意图切换、`Ctrl+Enter` 保存、`Esc` 取消 |
| 批注意图 | 修改 / 删除 / 疑问 三选一；疑问只要求 Agent 回答、不改文件，删除可直接留空意见 |
| 批注管理 | 右侧列表、定位、编辑、单条删除、批量清空、删除撤销提示 |
| 就地编辑 | 点击正文高亮或序号 pin，直接在批注旁弹出小编辑器；可改意见、切换意图、删除、取消/保存，不需要去右侧列表找 |
| 批注导航 | 点底部「这 N 条批注」展开浮层，列出当前文件（或全部）批注；`↑`/`↓` 实时切换并跳转，`Enter` 定位，`Esc` 关闭；面板关闭时可用 `Alt+↑` / `Alt+↓` 快速切换 |
| 待定高亮与序号 | 输入批注时正文保持蓝色虚线待定高亮；保存后正文右侧出现可点击的序号 pin |
| 全部批注总览 | 顶栏「全部批注」或侧栏「总览」打开：跨文件按文件分组，显示状态标签、时间、原文与意见；可按全部/待发送/已发送筛选、关键词搜索、定位、编辑、删除，或一键复制为 Markdown 清单 |
| 高亮联动 | Markdown/TXT/DOCX 用 `<mark>` 高亮，PDF 用页面归一化矩形覆盖；点击高亮打开对应批注 |
| 多文件 | 不同文档的批注合并计数、合并发送 |
| 持久化 | 批注写入插件数据目录；切换文件、关闭面板、重载页面后未发送批注仍在 |
| 启动恢复 | 只有上次文档仍有未发送批注时才自动打开它；否则显示空面板，并提供「打开上次文档」按钮 |
| 冲突检测 | 文件内容变化后自动重定位锚点；无法重定位时标记「位置待核对」；发送前再次校验哈希 |
| 发送 | 优先 `sendMessage`（`ui/message`）；宿主不支持时降级为 `updateModelContext`；两者都不可用时提供合并内容复制 |
| 修改后闭环 | 消息要求 Agent 先备份 `.bak`；发送后每 5 秒检查文件哈希，检测到修改时显示「刷新预览」横幅并重新定位批注 |
| 主题 | 跟随 ZCode 宿主深色 / 浅色主题 |

## 两种打开方式

- **内联（默认）**：对 Agent 说「打开文档批注面板」或「审阅 `docs/report.md`」。Agent 调用 `show_reviewer` / `open_document`，面板作为工具结果卡片出现在对话里，不需要去插件列表找入口。
- **侧栏**：用户明确要固定面板时，Agent 调用 `show_reviewer_sidebar`；也可以在插件菜单里打开。内联模式下顶部有「展开到侧栏」按钮（走 `ui/request-display-mode`）。

### 打开工作区外文件

左侧文件列表顶部的文件夹按钮（或空面板里的「打开工作区外文件」）可以打开工作区之外的文档：

- 输入文件的**绝对路径**，例如 `D:/papers/report.docx`；也可以点「浏览…」调用系统文件选择器；
- 支持 `.md` / `.markdown` / `.txt` / `.pdf` / `.docx`，单文件上限 100 MiB；
- 打开后顶部显示「工作区外文件」提示，批注和发送消息都会指向这个绝对路径，Agent 会修改原文件；
- 这个入口只对面板可见（`open_external_document` 和 `pick_external_document` 的 visibility 为 `app`），Agent 不能主动打开任意路径；用户打开后，该路径才会在本次服务会话内登记为可读。

系统文件选择器由 MCP 服务在本机弹出：Windows 使用 PowerShell 的 `OpenFileDialog`，macOS 使用 `osascript`，Linux 优先 `zenity`、回退 `kdialog`。如果系统对话框不可用，仍然可以手动输入绝对路径。

### 查看全部批注

面板顶栏的列表图标（或右侧批注栏顶部的「总览」）会打开总览弹窗：

- 按文件分组，组头显示文件路径与条数，每条带序号 `#1`、状态标签（待发送 / 已发送 / 位置待核对）和创建时间；
- 顶部三个分段按钮显示实时计数（全部 N / 待发送 N / 已发送 N），搜索框可匹配原文、修改意见和文件路径；
- 每条提供「定位」（关窗并跳到对应高亮）、「编辑」（把意见回填到输入框）、「删除」；
- 「复制全部」把当前筛选结果整理成按文件分组的 Markdown 清单，方便粘贴到别处；
- 已发送的批注仍保留在总览中，便于回看历史，但不会计入底部待发送数量。

### 就地编辑

点正文里的高亮，或右侧的序号 pin，会在批注旁弹出一个小编辑器：

- 文本框预填原来的批注意见，可直接修改；
- 顶部可切换「修改 / 删除 / 疑问」意图；
- 左侧垃圾桶删除这条批注（可撤销）；
- 「取消」或 `Esc` 放弃修改，「保存」或 `Ctrl+Enter` 提交；
- 点击编辑器外面、滚动文档或切换文件会关闭编辑器。

不需要再去右侧统一批注列表里找「编辑」。

### 快速批注导航

点底部「这 N 条批注」会展开一个浮层，按当前文档列出所有待发送批注（当前文档没有批注时显示全部文件的批注）。每条显示序号、意图、位置、原文和完整意见。

- `↑` / `↓`：实时切换选中项，并滚动到文档中的对应批注；
- `Enter`：定位并关闭浮层；
- `Esc` 或点击浮层外：关闭；
- 浮层关闭时，`Alt+↑` / `Alt+↓` 可以直接切换上一条/下一条批注；
- 底部「查看全部批注」跳到完整总览。

### 批注意图与修改后闭环

添加或编辑批注时可以选择三种意图：

- **修改**：按意见改写选中内容。
- **删除**：删除选中内容；如果是整段选区，Agent 会删除该段。意见可以留空，保存时自动填「删除这段内容」。
- **疑问**：只要求 Agent 回答，不要修改文件；等用户确认后再处理。

发送消息会逐条带上意图，并要求 Agent 在修改前把原文件备份为同目录的 `<原文件名>.bak`。发送成功后，面板每 5 秒检查一次文件哈希（最多 10 分钟）；一旦发现文档被修改，就在预览区顶部显示「刷新预览」横幅。点击后会重新读取文档、重新定位所有批注，定位失败的标为「位置待核对」。

### 启动时的恢复策略

只有上次文档仍然存在未发送批注时，面板才会在启动时自动打开它；如果批注已经全部发送，启动后就是空面板，不会再被上次文件占住。空面板里保留「打开上次文档」按钮，需要时可以手动打开。

### 关键设计

- **页面不直接读文件。** 所有文件访问都经过 MCP 服务的 `open_document` / 分片资源接口。
- **路径校验。** 默认只允许工作区：传入路径先 `path.resolve`，再做 `realpath`，拒绝工作区之外的绝对路径、`..` 穿越和符号链接逃逸。工作区外文件只能由用户在面板里通过「打开工作区外文件」主动输入绝对路径打开；对应工具仅面板可见，Agent 不能调用它。用户打开后，该路径才会被本次服务会话登记为可读。
- **只读。** 插件只读文档，不提供任何写文件工具；实际修改由主 Agent 用 ZCode 原生编辑工具完成。
- **锚点。** Markdown/TXT 记录字符区间、起止行号、前后 60 字上下文；PDF 记录页码、文本块索引、块内字符偏移与归一化矩形；DOCX 在预览文本上记录同样的区间，并额外记录**段落序号**和**原文第几次出现**。
- **重定位。** 文件哈希变化后先按偏移核对，再在 ±500 字范围内按原文搜索；仍找不到才标记为待核对，不会把旧选区硬套到新内容。
- **发送去重。** 发送成功后批注状态变为 `sent` 并写入 `batchId`，底部计数立即归零；重复点击不会重发同一批。
- **DOCX 边界。** Word 没有稳定的字符偏移，Mammoth 只负责生成预览；发送时会明确告诉 Agent「按文本匹配定位，请在 Word 原文中核对」，Agent 必须用 `docx` 技能或 python-docx 重新定位。

## Windows 安装

前置：Node.js 24+、ZCode Desktop（支持 Plugin UI 的版本）。以下命令在 PowerShell 或 Git Bash 中执行。

### 1. 构建

```powershell
cd "E:\1-研究生\00.ZCode_Project\01.ZCode设置\document-reviewer"
npm install
npm run typecheck
npm run build
npm run validate
npm run stage
```

`npm run stage` 会生成：

```text
dist\local-marketplace\
├── marketplace.json
└── plugins\document-reviewer\   # 可直接安装的完整插件
```

### 2. 安装到 ZCode

如果 `zcode` 命令不在 PATH，用 ZCode 自带的 CLI：

```powershell
$CLI = "D:\Program Files\ZCode\resources\glm\zcode.cjs"

node $CLI plugins marketplace add "E:\1-研究生\00.ZCode_Project\01.ZCode设置\document-reviewer\dist\local-marketplace" --scope user
node $CLI plugins install document-reviewer@document-reviewer-local --scope user
node $CLI plugins enable document-reviewer@document-reviewer-local --scope user
node $CLI plugins list --json
```

确认输出中 `document-reviewer@document-reviewer-local` 的 `enabled` 为 `true`，`diagnostics` 为空。

### 3. 在新会话中使用

**已启动的会话不会热加载新插件。** 按 `Ctrl+N` 新建会话（或重启 ZCode），然后直接说：

```
打开文档批注面板
```

面板会作为工具结果**内联出现在对话中**。也可以说「审阅 `document-reviewer/test-fixtures/sample.docx`」直接打开某个文件。

需要固定侧栏时，说「用侧栏打开文档批注面板」，或点面板顶部的「展开到侧栏」。

### 4. 卸载

```powershell
node $CLI plugins uninstall document-reviewer@document-reviewer-local --scope user
node $CLI plugins marketplace remove document-reviewer-local --scope user
```

插件数据位于：

```text
C:\Users\<你>\.zcode\cli\plugins\data\document-reviewer@document-reviewer-local\
```

卸载插件时该目录默认一并删除。

## 已知限制

1. **仅桌面本地工作区**。按官方约定，UI 面板用于 ZCode Desktop 本地工作区；Web、手机和远程工作区只会保留普通 MCP 工具。
2. **只读**。插件不会写回原文件，必须由 Agent 执行修改。
3. **格式**：`.md` / `.markdown` / `.txt` / `.pdf` / `.docx`。DOCX 原版预览可显示正文、表格、图片和大部分样式；复杂公式/域、批注、修订痕迹和嵌入对象可能不完整。Markdown 预览只读正文。
4. **单文件 100 MiB**。PDF 按 1 MiB 分片读取，面板资源单次读取上限 8 MiB；超大 PDF 首次打开会明显变慢。
5. **扫描版 PDF 无文本层**，只能看渲染结果，无法选中文字。本插件不做 OCR。
6. **PDF 选区跨页**时会自动拆成多条批注（每页一条，共用同一修改意见）。
7. **DOCX 定位是弱锚点**：字符偏移只针对转换后的 Markdown 预览，不对应 Word 内部位置；同名表述较多时可能定位到错误段落。消息里会带段落序号、出现次数和前后文，并要求 Agent 核对。
8. **锚点精度**：Markdown 渲染视图通过源码扫描映射偏移；极少数经过转义或实体编码的文本无法精确映射时会退化为块级锚点。
9. **已发送记录**只保留状态与 `batchId`，不追踪 Agent 是否真的完成修改（ZCode 没有回传处理结果的接口）。
10. **批注持久化按工作区隔离**；换工作区看不到另一工作区的草稿。
11. **主题**跟随宿主；不提供手动切换。
12. **意图只是语义标记**。插件本身仍然只读，删除/修改都由 Agent 执行；Agent 是否遵守取决于它读取结构化消息后的行为。
13. **刷新检测依赖文件哈希**。发送后轮询 5 秒、最多 10 分钟；如果 Agent 没有改文件，不会出现横幅；继续等待可以重新发送或手动刷新。
14. **序号 pin 由 DOM 矩形计算**。长文档使用 `content-visibility` 分块渲染，滚动或字体加载后会重新计算；极少数情况下（图片/字体异步加载）可能出现短暂偏移。
15. **`.bak` 备份是消息里的要求**，不是插件强制执行的；如果 Agent 没有备份，插件无法阻止它直接改原文件。
16. **工作区外文件**必须通过绝对路径或系统文件选择器打开，不会出现在左侧工作区文件列表中；登记只在本次 MCP 服务会话内有效，服务重启后需要重新打开。Windows 使用 PowerShell 文件对话框，macOS/Linux 为尽力支持；对话框不可用时仍可手动输入路径。
17. **DOCX 原版预览由 docx-preview 在浏览器渲染**，分页、表格、图片和大部分样式可保留；复杂 OMML 公式、域代码和分页可能与 Word 有差异。批注锚点仍基于转换后的 Markdown 文本，选中包含 Mammoth 忽略内容（如复杂公式）时可能无法定位。

## DOCX 实现与后续建议

已实现两种预览：

- **原版样式（默认）**：`docx-preview` 直接在面板内解析 DOCX 的 OOXML，渲染分页、段落、表格、图片、页眉页脚和大部分样式，并支持基础 OMML 公式。
- **Markdown**：Mammoth 的浏览器构建（`mammoth/mammoth.browser.js`，避免 Node `require` 与 ESM 打包冲突）生成 HTML，再用 `node-html-parser` 转成**干净 Markdown**（标题、段落、列表、表格、加粗/斜体、图片占位），作为批注锚点的规范文本。

两种模式共用同一份转换文本作为锚点：原版模式中的选区和已有批注高亮会通过 quote/上下文回找到这份文本；Agent 始终修改 Word 原文件。

原版预览会按文档区宽度自动缩放（0.35–2.0×）：侧栏展开/收起或窗口变宽时，由 `ResizeObserver` 重新计算，页面始终完整显示，不需要手动缩放。

后续可改进：

1. **精确锚点**：解析 OOXML 段落 ID（`w14:paraId`）与文本节点偏移，把锚点绑定到段落 ID，可比纯文本匹配稳得多；这是下一步最值得做的。
2. **公式与域**：docx-preview 已支持基础 OMML；复杂公式、域代码和自动编号仍可能与 Word 有差异。
3. **修订与批注**：读取 `w:ins`/`w:del`/`w:comment`，在预览中标记修订，工作量较大。
4. **分页**：docx-preview 按 Word 记录的显式分页符分页；长文档没有分页符时会显示为连续长页。
5. **其他格式**：`.html` 可直接复用选区模型；`.tex` 适合源码视图；`.csv` 适合表格选区。

## 安全说明

- 插件不向任何第三方服务器上传文档；页面不加载 CDN、字体或远程脚本。
- 页面运行在宿主沙箱中，无 Node / 任意文件系统权限；文件读取只能通过本插件 MCP 服务的受控接口。
- 所有路径都做 `realpath` 校验。默认限制在工作区内；工作区外文件必须由用户在面板中主动输入绝对路径打开，打开后才会登记到本次服务会话，Agent 不能调用外部打开工具。
- 发送的内容仅包括：工作区相对路径（外部文件则为用户打开的绝对路径）、文件哈希前缀、批注原文与上下文、用户修改意见。不包含文件全文。
- DOCX 原版预览由 `docx-preview` 在面板沙箱内解析，不联网；Markdown 转换在本地 MCP 服务进程内完成，不联网。
- 插件安装即授予代码执行信任；发布前请审查 `dist/server.mjs` 与 `dist/panel.html`。
