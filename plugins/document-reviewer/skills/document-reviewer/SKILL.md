# Document Reviewer

用户说“打开文档批注 / 审阅这份文档 / 我要在文档上做批注 / 按我的批注改文件”时，调用 `show_reviewer` 在对话中内联打开面板，不需要用户单独去插件页。

- 默认用 `show_reviewer`（内联卡片）。
- 只有用户明确说“用侧栏 / 固定面板 / 一直开着”时，才用 `show_reviewer_sidebar`。
- 已知具体文件时调用 `open_document`，参数是工作区相对路径，例如 `docs/report.md`；DOCX 也可以直接传。

面板打开后由用户自己阅读、选中文字并添加批注，不要替用户生成批注内容。

用户点击「批量发送」后，你会收到一条结构化消息，包含每条批注的文件、意图（修改 / 删除 / 疑问）、位置、原文、前后文和意见。处理时：

1. 逐条定位原文，确认位置正确。
2. 修改前把每个被修改的原文件备份为同目录下的 `<原文件名>.bak`；已有同名备份时追加时间戳，不要覆盖。
3. 「修改」按意见改写对应原文；「删除」删除选中内容（整段选区则删除该段），不要误删相邻内容；「疑问」只在回复中解答，不要改动文件，等用户确认。
4. 只修改批注要求涉及的内容，不重写未批注段落。
5. 不改变实验数据、统计结果、参考文献和科学含义。
6. 无法可靠定位时明确说明，不要猜测位置。
7. 修改完成后按 `[批注 N] 已修改 / 无需修改 / 无法定位：说明` 的格式返回逐条清单，并提示用户在面板中点击「刷新」查看更新后的文档。

## DOCX

`.docx` 的预览是 Mammoth 转出的 Markdown，字符偏移只针对预览文本，不对应 Word 内部位置。消息里会给出原文、前后文、段落序号和“第几次出现”。修改 DOCX 时：

- 以原文和前后文在 Word 文件中重新定位，不要按字符偏移硬套。
- 用 `docx` 技能或 python-docx 修改，保留样式、修订和页眉页脚。
- 如果原文在 Word 中找不到或存在多处相同表述，说明情况，不要猜。

工具可能带插件命名空间（如 `plugin:document-reviewer:reviewer:show_reviewer`），按实际工具名为准。
